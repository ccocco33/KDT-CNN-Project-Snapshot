# 어플리케이션 설명

1. 앱 개요
   - 핵심 기능: 모두가 웃고, 눈 감지 않은 단체 사진.
   - 개발 배경: 단체 사진을 잘 찍는 것은 언제나 어려움. 한명쯤은 미소 짓지 않고, 한명쯤은 눈을 감음. 이러한 불편함을 해결해보고자 개발.
   - 구현 방법: CNN 모델 기반으로 웃는 얼굴과 감은 눈을 검출.
   - 개발 목표  
       - 모델 성능: 웃음 및 눈 검출율 95% 이상
       - 판정 속도 xx ms 이하.

2. 환경
   - 구동 환경
       - 라즈베리파이: 4cores / 8gb mem / debian
       - 모니터: 라즈베리파이를 연결할 로컬 PC
       - LAN을 통해 ssh 통신. xserver 기반 로컬 pc에 UI 실행
    - 테스트 환경
        - docker로 같은 환경 구성하여 테스트

3. 사용 기술
    - python
    - LiteRT, OpenCV
    - 협업 : git, google drive

4. 요구사항
    - 기능 요구사항
        1. 초기화면
           - 앱 이름과 사진 촬영 시작 버튼 표시
           - 촬영 시작 버튼을 누르면 미리보기로 넘어감.
           - 화면 하단에 "N명 이상 촬영시 앱이 느려질 수 있습니다." 라는 문구를 추가
        2. 미리보기 (구도를 잡는 단계)
            - 사용자는 화면에서 카메라 미리보기를 볼 수 있음.
            - 미리보기에서는 사람 수를 띄워줌.
            - 미리보기 화면 아래에 "손가락을 펴고 들면 사진 촬영이 시작됩니다." 문구 표시.
            - 얼굴이 너무 작은 사람이 있으면, 해당 얼굴에 바운딩 박스를 치며 "조금 더 가까이 와주세요" 문구를 띄움.
            - 얼굴이 보이지 않는 사람(옆모습, 가림 등)이 있으면, 해당 얼굴에 바운딩 박스를 치며 "얼굴이 보이도록 해주세요" 문구를 띄움.
            - 사용자는 촬영을 시작하는 제스처를 취하면, 촬영이 시작됨.
            - 안내 문구(가까이, 얼굴이 보이지 않음)가 떠 있는 동안에는 손을 들어도 촬영을 시작하지 않음.
            - 안내 문구는 같은 상황이 잠시(약 0.5초) 이어질 때 띄우고, 상황이 풀린 뒤에도 잠시 확인한 후 지움. (순간적인 오판으로 문구가 깜빡이거나 촬영이 막히지 않도록)
        3. 촬영
            - 촬영은 준비와 촬영단계로 나뉨.
            - 사진 촬영 시간은 최대 준비 제한 시간과 촬영 제한 시간의 합임. (기본값: 12초 = 10초(준비) + 2초(촬영))
            1. 준비 단계 (미소를 짓는 단계): 촬영을 시작되면 앱이 조건을 확인하기 시작함.
                - 미소 짓지 않는 사람이 있는 경우에 특정 얼굴에 바운딩 박스를 치며 "미소 지어주세요"라는 문구를 띄움.
                - 모두 웃는 순간부터 바로 촬영 단계로 넘어감.
                - 준비 시간동안 웃지 않는 사람이 있으면, "웃지 않으신 분이 있어 촬영을 취소했어요. 준비되면 다시 손을 들어 촬영을 시작해주세요."라는 문구 후에 미리보기로 돌아감.
            2. 촬영 단계 (사진을 찍는 단계)
               - 촬영 시간 동안 연속으로 사진을 여러장 찍음.
               - 찍은 사진은 모두 저장.
        4. 결과
           - 조건을 충족하는 사진을 최대 5장 제시.
           - 조건을 충족하는 사진이 없을 때, 조건에 가장 가까운 사진을 최대 5장 제시하고 "모두 조건에 맞는 사진은 없어요. 가장 가까운 사진을 보여드려요" 문구를 띄움. (판정이 엄격해 조건 충족 사진이 없을 때도 찍은 사진을 받을 수 있도록)
           - 사진이 한 장도 없을 때 (모든 사진에서 얼굴이 검출되지 않음), "조건에 맞는 사진이 없어요" 문구를 띄움.
           - 미리보기 화면으로 돌아가는 버튼 표시.
        5. 기타
           - 촬영 단계(해당 단계 내 준비와 촬영 모두 포함)를 제외한 모든 단계에서 초기화면으로 돌아갈 수 있어야 함.
           - 카메라 연결이 끊기면 카메라 화면 대신 "카메라 연결을 확인해 주세요" 문구를 띄움. 카메라가 다시 연결되면 사용자가 앱을 다시 켜지 않아도 원래 화면으로 돌아옴.
           - 촬영 중(준비, 촬영)에 카메라 연결이 끊기면 촬영을 취소하고 미리보기로 돌아감. 다시 연결되면 손을 들어 촬영을 다시 시작할 수 있음.
    - 비기능 요구사항
        1. 최대 촬영 가능 인원을 명시해야함.
        2. FPS
           - 촬영 속도 20FPS 이상.
           - 화면 속도 15 FPS 이상.
           - 판정 속도 5 FPS 이상.
        3. 사진 선택.
           - 조건에 맞는 사진을 찍힌 순서로 나열한 후 장수대로 n개 구간으로 나누고, 구간마다 눈을 가장 크게 뜬 사진을 1장씩, 총 n개의 사진을 선택.
           - 눈을 뜬 정도는 사진 속 사람 중 눈을 가장 작게 뜬 사람 기준. (눈을 감으려는 순간처럼, 조건은 충족했지만 눈이 작아진 사진을 피하기 위함)
        4. 사진 저장.
           - 촬영 시에는 촬영한 모든 사진을 디스크에 저장.
           - 결과 화면을 벗어나는 경우에 결과로 보여준 사진만 저장하고 나머지 사진은 삭제.
        5. 얼굴 판정 기준.
           - 최소 얼굴 높이: 50px 이상 (카메라 640x480 기준, 약 2.3m 거리). 미만이면 미리보기에서 안내.
           - 얼굴이 보이지 않음: 얼굴은 검출되지만 입이 보이지 않거나 두 눈이 모두 보이지 않는 얼굴 (옆모습, 가림). 웃음과 눈을 판정하지 않음. 미리보기에서 안내.
           - 한쪽 눈만 가려진 얼굴(앞머리 등)은 보이는 얼굴로 보고, 보이는 눈으로 판정. (본인 스타일일 수 있어 촬영을 막지 않음)
           - 단, 선글라스류(선글라스, 색이 짙은 고글 등)로 눈이 보이지 않는 경우는 보이는 얼굴로 보고, 눈 조건을 충족한 것으로 처리. 웃음은 입으로 판정. 투명한 안경은 눈이 보이므로 눈을 그대로 판정.
           - 한계: 다른 사람이나 물건에 많이 가려진 얼굴은 얼굴로 검출되지 않을 수 있으며, 이 경우 안내와 판정에서 빠짐.

5. 구현 결정에 필요한 사항
   - X Forwarding 방식이 느리면 다른 방식을 고려.
