# 발표 Threshold 결정 정리

- 근거: `docs/dev_spec.md` 10절 11번 ~ 15번, 17번
- 수치는 모두 WIDER holdout (가로 640). 기준값은 dev 에서 정하고, 정할 때 보지 않은 holdout 으로 확인

## Threshold 란

- 모델 점수 (0~1) 를 판정 (웃음 / 안 웃음 등) 으로 바꾸는 기준값
- 올리고 내림에 따라 두 오류가 맞바뀜: 놓침 (recall 하락) <-> 잘못 통과 (오판 증가)
- 학습 노트북 기준값은 학습 데이터에서 정한 값이라 단체 사진에 그대로 맞지 않음
  - smile 0.757: 웃음 recall 64% (웃는 사람 셋 중 하나를 놓침)
  - eye 0.459: 감은 눈 recall 47%
  - occlusion 0.569: 보이는 얼굴 오판 3.4% (목표 2%)

## 앱에 대한 전제

- 촬영 한 번에 약 40장을 찍고 조건에 맞는 사진을 최대 5장 보여줌 -> 일부를 놓쳐도 결과는 나옴
- 조건에 맞지 않는 사진 (눈 감음, 안 웃음) 이 결과로 나가면 앱의 약속을 어김
- 감은 눈은 드물고 잠깐. 뜬 눈을 감음으로 보면 그 프레임만 빠짐
- 약한 미소가 있음: 본인은 웃었지만 남이 보면 안 웃은 것처럼 보임 (thinkcat 판단)
- PREVIEW 에서 보이는 얼굴을 "안 보임" 으로 보면 촬영 시작이 막힘

## 전제를 지표로 표현

| 판정 | 더 피할 오류 | 우선 지표 | 이유 |
|---|---|---|---|
| 얼굴 검출 (`SCORE_TH`) | 조건 안 맞는 사진 통과 | 사진 precision | 40장 중 일부를 놓쳐도 결과는 나옴 |
| 눈 (`EYE_TH`) | 감은 눈을 뜸으로 | 감은 눈 recall | 결과 사진에 그대로 나감 |
| 웃음 (`SMILE_TH`) | 웃음을 놓침 | 웃음 recall | 약한 미소를 놓치면 촬영 시작, 결과 선택에서 계속 떨어짐 |
| 가림, 고개 돌림 (`OCC_TH`, `YAW_TH`) | 보이는 얼굴을 안 보임으로 | 보이는 얼굴 오판 | 촬영 시작이 막힘. 놓친 얼굴은 뒤 단계에서 걸러짐 |

## 지표를 설정하는 방법

- 모델을 바꾸면 점수 분포가 달라져 기준도 다시 맞춤 (v0.0.6 smile 0.5 -> 0.31, eye 0.8 -> 0.84)

| 기준 (현재) | holdout 결과 |
|---|---|
| `SCORE_TH` 0.7 | 사진 precision 89% (0.9 에서는 72%. dev 만 측정) |
| `EYE_TH` 0.84 | 감은 눈 recall 93%, 뜬 눈을 감음으로 20% |
| `SMILE_TH` 0.31 | 웃음 recall 77%, 안 웃음을 웃음으로 10% |
| `OCC_TH` 0.86 | 보이는 얼굴 오판 1.7%, 가림 recall 63% |
| `YAW_TH` 0.6 | 보이는 얼굴 오판 2.6%, 옆모습 69% 거름 |
