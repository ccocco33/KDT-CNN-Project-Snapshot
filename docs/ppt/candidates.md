# 발표 문제해결 후보와 실패한 시도

- 이미 정리한 것: 학습 데이터 전처리와 증강, 선글라스 반사 오판 (`problem_solving.md`), Threshold 결정 (`threshold.md`)
- 틀: 문제 인식 -> 원인 분석 -> 해결 방안 -> 적용 결과. 수치는 WIDER holdout (기준값을 정할 때 보지 않은 사진), 가로 640 (다른 조건은 따로 표기)
- 근거: `docs/dev_spec.md` 10절 (번호 표기), `docs/model_versions.md`

## 문제해결 후보

### 1. 가림 판정 (dev_spec 10절 9, 12번)

- 문제: 손, 앞사람, 물건에 가린 얼굴을 못 잡음. yaw 규칙은 가린 얼굴의 4% (2/46) 만 잡음
- 원인: yaw 는 고개 돌림만 봄. FaceLandmarker 미검출로 잡으면 70% 지만 보이는 얼굴 오판이 10%, 얼굴당 약 14ms 추가
- 해결: 가림 기준 재정의 (입 또는 두 눈이 안 보이면 가림. 한쪽 눈, 선글라스, 수염은 보임. thinkcat) -> WIDER 재검수 -> 가림 CNN 학습 (COFW 실제 가림 검수 + 합성)
  - v0.0.4 가 본인 손으로 가린 입을 못 잡음 (앱 촬영) -> 얼굴과 색이 같은 가리개가 학습에 없었음 -> 피부색을 맞춘 합성 추가 (v0.0.5)
- 결과: AUC 0.912 (v0.0.4) -> 0.969 (v0.0.5). `OCC_TH` 0.86 에서 가림 recall 63%, 보이는 얼굴 오판 1.7%
- 한계: 두 눈 가림과 선글라스 구분이 약함 (두 눈 가림 실제 데이터 COFW 3장뿐), 헬멧, 가면

### 2. 얼굴 검출 2단계 (dev_spec 10절 7번)

- 문제: 전체 화면에 FaceLandmarker 를 돌리면 단체 사진 얼굴의 17% (86/502) 만 검출. 80px 미만 얼굴은 거의 못 찾음
- 원인: FaceLandmarker 는 가까운 얼굴 몇 개용
- 해결: YuNet 으로 얼굴을 먼저 찾고, 잘라낸 얼굴에 판정 모델 적용
- 결과: 검출 68% (339/502). 사진별 검출 수로 비교한 대략값 (WIDER val 114장)

### 3. 최소 얼굴 높이 50px (dev_spec 10절 5번)

- 문제: 작은 얼굴에서 눈 판정이 크게 틀림
- 원인 (blendshape 뜬 눈을 감음으로 오판): 30~40px 27%, 40~50px 22%, 50~60px 13%, 60~80px 9%, 80px 이상 6% (dev 만 측정)
- 해결: 50px 미만 얼굴은 "가까이 오세요" 안내 (요구사항으로 반영)
- 결과: 카메라 640x480 기준 약 2.3m 이내, 화면 가로 약 2.8m 폭

### 4. 보임 기준 변경과 고개 돌림 기준 (dev_spec 10절 9, 15번)

- 문제: 앞머리 등으로 한쪽 눈만 가려도 촬영이 막힘. `YAW_TH` 0.5 에서 보이는 얼굴의 4.2% 가 막힘 (가림 CNN 오판 2% 보다 큼)
- 원인: 처음 기준은 "두 눈과 입이 모두 보여야 보임". 0.5 는 이 기준 때 정한 값
- 해결: 보임 = 입 + 눈 한쪽 이상 (thinkcat), `YAW_TH` 0.6 (thinkcat)
- 결과: 한쪽 눈 가린 얼굴 (COFW 74장) 의 62% 를 eye 가 뜸으로 판정. 보이는 얼굴 오판 2.6%, 옆모습 69% 잡음 (0.5: 75%)

### 5. 투명 안경 반사로 감은 눈을 뜸으로 (dev_spec 10절 13번)

- 문제: 앱 촬영에서 투명 안경에 반사가 비친 감은 눈을 뜸 (0.804) 으로 판정해 결과 사진에 포함
- 원인: 안경테, 반사를 "뜸" 의 단서로 씀. 학습 데이터에 안경 쓴 감은 눈이 적음
- 해결: eye 재학습 (v0.0.3): 투명 안경 합성 증강, 눈 뜸 정도 4단계 라벨 (검수), 눈 모양 기하 지표 교사
- 결과: 기준 0.8 에서 감은 눈 recall 83% -> 92% (당시 라벨)

### 6. 손 들기 판정 (dev_spec 4절)

- 문제: 손등을 보여도 촬영이 시작됨. 손바닥만 허용하고 싶었음
- 원인: HandLandmarker 의 왼손, 오른손 구분이 흔들려 손바닥, 손등 판정이 불안정
- 해결: 손바닥, 손등 구분을 빼고 "손가락 3개 이상 펴고 위로" 로 단순화. 안내 문구를 "손가락을 펴고 들면 사진 촬영이 시작됩니다." 로 (thinkcat)
- 결과: 주먹, 옆으로 든 손은 제외. 판정 정확도는 수치로 측정하지 않음

### 7. 판정 결과가 다른 단계로 넘어오는 오류 (앱)

- 문제: PREVIEW 화면에서 guidance ValueError 로 앱이 멈춤
- 원인: 판정 스레드가 PREPARE 요청으로 만든 결과가 PREVIEW 로 넘어온 뒤 도착 (요청 항목이 다름)
- 해결: 결과에 요청 항목을 기록하고, 현재 단계가 필요로 하는 항목이 없는 결과는 버림 (`accepts`)
- 결과: 재현 테스트 추가 (pytest)

### 8. 모델 평가 화면 (dev 모드)

- 문제: 앱 촬영에서만 보이는 오판 (선글라스 반사, 본인 손 가림) 을 재현하고 기록할 방법이 없음
- 해결: 모델, 판정 항목을 골라 점수, 기준값, 판정을 얼굴마다 표시. 찍기, 연속 촬영 (0.5초 간격) 으로 사진과 점수를 json 과 함께 저장
- 결과: 거리를 바꿔 가며 찍은 사진으로 "얼굴 약 120px 이상에서 반사 오판" 을 확인 -> 문제해결 2 의 출발점

### 9. 평가 세트 구축

- 문제: 학습 test 점수는 높은데 실제 단체 사진 성능을 알 수 없음 (v0.0.1 smile 학습 test 0.943 -> 단체 사진 0.831, eye 0.985 -> 0.725)
- 해결: WIDER FACE 단체 사진에 얼굴별 보임, 웃음, 눈 라벨을 직접 검수 (라벨 도구). 기준을 정하는 dev 와 확인용 holdout 으로 나눔. 보임 기준이 바뀐 뒤 가림 라벨 재검수
- 결과: 사진 1,040장, 얼굴 3,938개 라벨. 평가 대상 (부적절 사진 제외) dev 514장, holdout 509장. 모든 모델, 기준값 비교의 공통 기준

## 실패한 시도

| 시도 | 기대 | 결과 | 교훈 |
|---|---|---|---|
| eye 에 얼굴 전체 입력 (학습 1307) | 입력을 smile 과 맞춰 모델 결합 가능 | AUC 0.934 -> 0.897 (당시 라벨) | 눈 판정은 눈 영역을 크게 보는 게 중요 |
| 앱 입력을 64px 로 줄였다 넣기 | 학습 데이터 해상도와 맞춤 | WIDER, 선글라스 판정 거의 같음 | 해상도 차이는 주된 원인이 아님 |
| 합성 반사 렌즈 증강 재학습 (eye 1907, 1936, smile 1921) | 반사 선글라스 오판 감소 | WIDER 같음, 선글라스 개선 2~3명, 앱 촬영 거의 그대로 | 합성은 실제 반사를 대신하지 못함 -> 실제 데이터, 입력 변경으로 해결 |
| eye 1907 (조기 종료로 30 epoch 에서 멈춤) | - | AUC 0.906 으로 하락 (v0.0.5 0.933) | 학습률이 내려가기 전에 멈춤. patience 를 늘려 끝까지 학습 (1936: 0.924) |
| smile 백본 MobileNetV3 Large (0239) | 큰 모델로 성능 향상 | +0.009 | 모델 크기보다 데이터가 중요. Small 유지 |
| 가림을 FaceLandmarker 미검출로 판정 | 추가 학습 없이 가림 판정 | 가림 70% 잡지만 보이는 얼굴 오판 10% | 촬영을 너무 자주 막음 |
| 가림을 YuNet 신뢰도 < 0.8 로 판정 | 추가 모델 없이 가림 판정 | 가림 recall 20% | 얼굴처럼 보이는 정도일 뿐 가림과 직접 관련 없음 |
| 가림 CNN + YuNet 신뢰도 합친 규칙 | 서로 다른 가림을 잡음 | 가림 recall 50% -> 52% 에 보이는 얼굴 오판 1.4% -> 2.4%, 기준값이 둘 | 확실한 개선이 아니라 CNN 단독 |
| 손바닥, 손등 구분 | 손바닥만 허용 | 손등도 통과 | 모델 출력 (왼손, 오른손) 이 흔들림 -> 규칙 단순화 |
| int8 양자화 | 추론 속도 향상 | AUC 하락 (eye 0.934 -> 0.889, occlusion 0.969 -> 0.914), XNNPACK 사용 불가라 빠르지도 않음 | fp32 유지. dynamic 은 AUC 같으나 이득 작음 |
| colima (Linux VM, 4코어) 로 라즈베리파이 속도 흉내 | 같은 자원 조건 비교 | 같은 코드도 측정마다 2~3배 흔들림. 한때 "yunet_cnn 이 느려짐" 으로 잘못 결론 | 속도는 실기기에서 반복 측정 필요 |
| 모델 결합 (smile, eye, occlusion 백본 하나) | 추론 시간 감소 | 검토만 (CHECKING 에서 얼굴당 약 13ms -> 5ms 예상. 입력이 모두 달라 어려움) | 진행 안 함 (thinkcat) |
