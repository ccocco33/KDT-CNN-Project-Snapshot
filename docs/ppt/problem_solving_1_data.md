# 문제해결과정 1: 학습 데이터와 단체 사진의 분포 맞추기

## 문제해결과정 1 요약본

- 전제: WIDER 단체 사진 holdout 을 앱이 실제로 찍을 사진을 대표하는 평가 세트로 봄
- 문제 인식: 학습 test 에서는 높은 성능이 단체 사진 평가 세트에서 크게 떨어짐 (eye, smile 모두)
- 원인 분석: 학습 데이터와 단체 사진 얼굴의 분포 차이
  - eye: 얼굴 크기. 단체 사진 얼굴은 절반 이상이 60px 미만, 학습 데이터에는 거의 없음. 작은 얼굴에서 성능이 특히 낮음
  - smile: 윤곽 세기. 학습 얼굴 (GENKI) 은 윤곽이 또렷하고 단체 사진 얼굴은 뭉개져 있음. 얼굴 크기와 무관하게 고르게 낮음
- 해결 방안
  - 전처리: 앱과 같은 방식으로 다시 자르기, 64px 통일, 흑백 제외 (입력 모양을 앱과 맞춤)
  - 증강: 저해상도, 흐림, 회전, 밝기, 대비, 채도 (분포를 단체 사진 쪽으로 넓힘)
- 적용 결과: eye 0.725 -> 0.933 (베이스라인 0.908 초과), smile 0.831 -> 0.889
- 한계: 같은 단계에 학습 노트북 변경도 섞여 전처리, 증강만의 효과는 나누지 못함

## 문제해결과정 1 지표본

### 측정 조건

- 평가 세트: WIDER 단체 사진 holdout (기준값을 정할 때 보지 않은 사진), 가로 640, YuNet 검출, 보이는 얼굴, 앱과 같은 자르기
- 분포 비교: 학습 데이터 (원본, 전처리 후, 전처리 + 증강 후) vs WIDER holdout 얼굴
  - 얼굴 해상도: 얼굴 박스 높이 x 실제 정보가 담긴 한 변 (px)
  - 윤곽 세기: 128px 로 맞춘 흑백 이미지의 라플라시안 분산. 저해상도, 흐림, 압축으로 낮아짐
  - 구분 AUC: 그 특성 하나로 학습 데이터와 WIDER 를 가르는 AUC. 0.5 에 가까울수록 두 분포가 비슷
- 스크립트, 결과
  - 분포 비교: `tmp/cnn_data_check/domain_gap.py`, `tmp/cnn_data_check/results/domain_gap/{eye,smile}/summary.txt`
  - AUC: `tmp/group_photo_eval/version_auc.py`, `smile_runs_auc.py`, `eye_retrain_compare.py`, `tmp/v001_test/measure.py`

### 문제 인식: 학습 test 와 단체 사진 AUC

| 모델 | 학습 test | WIDER holdout | 베이스라인 blendshape |
|---|---|---|---|
| eye v0.0.1 | 0.985 | 0.725 | 0.908 |
| smile v0.0.1 | 0.943 | 0.831 | 0.933 |

### 원인 분석: eye 얼굴 해상도 차이

| 특성 | WIDER holdout | 학습 원본 |
|---|---|---|
| 얼굴 해상도 중앙값 | 58px | 155px |
| 60px 미만 얼굴 비율 | 53% | 4% |
| 해상도만으로 구분 AUC | - | 0.897 |

- 단체 사진 60px 미만 얼굴의 eye AUC 0.69~0.72 (작은 얼굴에서 특히 낮음)

### 원인 분석: smile 윤곽 세기 차이

| 특성 | WIDER holdout | GENKI 원본 |
|---|---|---|
| 윤곽 세기 중앙값 | 165 | 389 |
| 윤곽 세기만으로 구분 AUC | - | 0.798 |

- 얼굴 크기 구간별 smile AUC 0.80~0.86 (전 구간 고르게 낮음)

### 해결 방안: 전처리와 증강 설정

- 전처리 (`training/data/{eye,smile}/preprocessed/preprocess.py`)
  - YuNet 으로 다시 자름: 박스 높이 정사각형 (앱과 같은 모양)
  - 64x64 로 통일
  - 흑백 제외 (eye 는 opened 11장, closed 72장)
- 증강 (학습 노트북)
  - 저해상도: 확률 0.5 로 24~56px 로 줄였다 키움
  - 흐림: 확률 0.2, 가우시안 시그마 최대 1.2
  - 회전 20도, 확대/축소, 이동, 좌우 뒤집기
  - 밝기, 대비, 채도

### 해결 방안: 분포 차이가 줄어든 정도

| 특성 | WIDER | 학습 원본 | 전처리 후 | 전처리 + 증강 |
|---|---|---|---|---|
| eye 60px 미만 얼굴 비율 | 53% | 4% | 6% | 59% |
| eye 학습 범위보다 작은 WIDER 얼굴 | - | 60% | 53% | 1% |
| eye 해상도 구분 AUC | - | 0.897 | 0.598 | 0.585 |
| smile 윤곽 세기 중앙값 | 165 | 389 | 353 | 153 |
| smile 윤곽 세기 구분 AUC | - | 0.798 | 0.789 | 0.523 |

- 학습 범위: 학습 데이터 p5~p95
- 전처리만으로는 분포 차이가 거의 줄지 않음. eye 윤곽 세기는 오히려 벌어짐 (학습 범위보다 흐린 WIDER 얼굴 2% -> 43%). 증강 후 7%

### 적용 결과: 단체 사진 AUC

| 모델 | 이전 | 이후 | 비고 |
|---|---|---|---|
| eye | 0.725 (v0.0.1) | 0.933 (v0.0.3) | 베이스라인 0.908 초과 |
| eye 60px 미만 얼굴 | 0.69~0.72 | 0.90~0.94 | |
| smile | 0.831 (v0.0.1) | 0.879 (전처리 + 증강) -> 0.889 (v0.0.2, EMA, 증류 등) | 증가분의 약 83% 가 첫 단계 |

### 한계

- 첫 단계에 학습 노트북 변경 (팀 노트북 -> 새 노트북) 도 섞여 전처리, 증강 각각의 기여는 나누지 못함
- 평가 세트의 감은 눈이 적음 (holdout 59명). 구간별 수치는 흔들림이 큼
- WIDER 를 앱 촬영 사진의 대표로 보는 전제 자체의 한계
